# Seedream 5.5 benchmark — 2026-11-14

Default-model migration is supported by the measured product-editing behavior, native RGBA workflows, finer layer splitting and usable rich-text OCR. It is **not** supported by a claim that every edit preserves pixels, that all glass is truly translucent, or that 5.5 universally outperforms Pro on typography.

## Scope and reproducibility

- Models: `doubao-seedream-5-5-261028` and `doubao-seedream-5-0-pro-260628`.
- **76 benchmark requests, 76 successful responses, 125 downloaded output images.** Additional real CLI smoke checks: one transparent generation and one OCR decomposition returning six assets. Overall: **78 image-API requests and 132 downloaded assets**.
- These are API/download success counts, not visual-quality pass rates. Both good and failed visual outcomes are retained.
- Main suite: one shared 5.5-generated product photograph; two 12-round product-color chains; two six-round short-prompt poster-title chains; one six-round refined-prompt 5.5 poster chain; 12 matched typography samples; two 2K typography checks; two fusion samples; four realism samples; six alpha samples; five decompositions; two single-step prompt controls.
- Matched editing tests use the **same initial source**, size, prompt and standard optimization across models. Text generation has two repetitions per prompt/model; most other tasks have one sample. Source photo was generated by 5.5, which is a potential source-distribution bias.
- PNG, no visible watermark, opaque background for ordinary editing. Explicit 1024×1024 for product chains and 1536×1024 for poster chains/primary typography. The two extra tea posters use the **2K preset**; 1536×1024 primary typography should not be mislabeled 2K.
- Four concurrent requests, with ordered dependencies inside each chain. API timing measures the POST response; download-inclusive elapsed time is separately recorded. Task scheduling and service load are not controlled experiments.
- No seeds, deterministic provider setting, blinded human panel, confidence interval, calibrated colorimetry or 100-round stress test. Product colors and Chinese/English text were visually checked, including an independent agent review. Arabic was not graded for exact correctness.

[Sanitized per-request payloads, hashes, response metadata and analysis](seedream55-results.json) retain the evidence without credentials, data URLs, signed response URLs or absolute local artifact paths. Raster outputs stay outside the repository. The source/fixture hashes identify the actual inputs; cross-host font substitution may change a regenerated fixture.

Reproduce paid requests deliberately:

```bash
uv run evals/seedream55_benchmark.py --run --out-dir /absolute/private/seedream55-results
uv run evals/analyze_seedream55.py /absolute/private/seedream55-results
# Optional deterministic local Chinese-title demonstration with an available font:
uv run evals/analyze_seedream55.py /absolute/private/seedream55-results \
  --localization-font /absolute/path/to/chinese-font.ttf
```

The benchmark persists each completed/failed/in-flight job before proceeding. Reruns reuse saved results, including errors and unknown outcomes; deliberately remove a failed job directory only after deciding that a fresh paid submission is warranted. `--fixture-font` supplies a local Latin font; macOS Arial or Pillow fallback is used otherwise.

## Product editing: target change and protected-region stability

A generated RGB photo contains a red ceramic cup at left, a lemon and a blue vase with a white flower. Each round recolors only the cup body/handle: dark blue → orange-yellow → dark green → purple → white → red, repeated twice. Each model receives the previous round's output.

Both models achieve **12/12 broadly correct exterior cup colors** on visual review. This does not establish complete material/shape/interior fidelity. White cup interiors introduced at round 5 persist through several later exterior-color changes; the prompt did not explicitly control interior color.

Protected-region metrics exclude a conservative normalized rectangle `[0.05, 0.30, 0.62, 0.95]` around the cup. MAE is mean absolute RGB error on 0–255 values. “Changed >32” counts pixels whose maximum channel difference exceeds 32. Results below compare round 12 to the **original**, not merely to round 11.

| Metric | 5.5 | 5.0 Pro |
|---|---:|---:|
| Exterior color targets correct | 12/12 | 12/12 |
| Protected-region MAE, round 12 | **6.05** | 21.54 |
| Protected-region PSNR | **31.93 dB** | 19.38 dB |
| Protected pixels changed >32 | **0.00%** | 45.00% |
| Protected pixels changed >8 | **11.05%** | 96.40% |
| Exactly identical protected pixels | 0.54% | 0.003% |
| Mean signed RGB change | −5.99 | −9.99 |
| Median API time per edit | **9.25 s** | 16.52 s |

5.5 keeps the vase/flower/table substantially cleaner. Pro accumulates conspicuous roughness, cold exposure and damaged material/flower detail. **5.5 still darkens and changes pixels**: zero pixels above a 32-level threshold is not zero pixel drift. These observations concern one scene and one chain per model.

## Fixed-layout poster editing: failure and prompt refinement

A locally drawn 1536×1024 poster has an upper-left title, three small-print lines and three geometric shapes. Six rounds replace the title and finally restore “GREEN STUDIO”. The initial prompt names the change and asks to preserve font, position, small print, shapes, colors and background.

5.5 changes the title correctly but **shrinks and recenters the design in round 1**, adding paper texture. Pro preserves geometry better initially, then accumulates substantial grain and glyph/shape degradation. A cleaner final appearance and original-layout fidelity are separate outcomes.

| Protected-region metric, round 6 vs original | 5.5 short prompt | Pro short prompt | 5.5 refined prompt |
|---|---:|---:|---:|
| MAE | 34.98 | 12.80 | **3.02** |
| PSNR | 11.30 dB | 21.83 dB | **35.88 dB** |
| Pixels changed >32 | 26.44% | 19.71% | **0.14%** |

The mask excludes the original title strip: normalized `[0.02,0.02,0.98,0.20]`. The 5.5 refined chain adds a title bbox and explicit original-position/font-size/whitespace constraints:

> 只修改图1 `<bbox>58 64 512 175</bbox>` 内的标题，把“GREEN STUDIO”改成“BLUE STUDIO”。严格保持文字原来的左上角位置、字号、颜色和字体。框外所有像素保持原样，不调整布局、不增加纹理、不移动色块、不改变留白，保持1536×1024画布。

The corresponding six-round chain preserves approximate layout and correct titles, but still adds texture and darkens slightly. Two one-step controls—this Chinese recipe and an explicit English geometry-preservation recipe—also retain layout much better than the original short prompt. Several changes were introduced together; these tests **do not isolate bbox efficacy, language preference or universal reliability**. For exact copy/geometry, use local text replacement after decomposition.

## Native transparency

All **six** 5.5 alpha samples decode as RGBA and contain real transparent pixels. The text-only logo, ceramic teapot, RGB cup extraction, two-reference extraction and auto-background leaf all exercise the expanded input/parameter surface. The two-reference request returns **one combined image**, not independently downloadable layers.

| Sample | Fully transparent pixels | Partial-alpha pixels |
|---|---:|---:|
| Auto-background leaf | 63.18% | 0.45% |
| RGB photo → cup cutout | 88.39% | 0.43% |
| Glass/water cup | 74.43% | 0.37% |
| Chinese/English logo | 94.55% | 1.06% |
| Two-reference asset collage | 65.31% | 0.98% |
| Ceramic teapot + shadow | 47.89% | 5.47% |

The glass cup is a **semantic failure for interior transparency**: alpha is 255 throughout inspected interior rectangles `[450,400,650,550]` and `[500,200,600,300]`. Its exterior is transparent, but the interior will not reveal a new underlying background. Partial-alpha edge pixels alone cannot establish translucent glass. The teapot has a usable soft-alpha shadow in this sample; this does not establish general refraction/edge quality.

## Decomposition and OCR

| Input / configuration | Returned outputs, including base | API time | Recomposition PSNR |
|---|---:|---:|---:|
| Poster, 5.5 max_images=6 + OCR | 6 | 16.56 s | 25.20 dB |
| Poster, 5.5 max_images=20 + OCR | 8 | 22.57 s | 25.11 dB |
| Product photo, 5.5 max_images=10 + OCR | 5 | 15.17 s | 21.42 dB |
| 25 separate colored shapes, 5.5 max_images=40 | **26 (base + 25)** | 56.36 s | 35.22 dB |
| Poster, Pro default decomposition | 9 | 48.68 s | 29.75 dB |

The 25-shape sample **actually exceeds the legacy 16-foreground limit**. It validates extended layer handling, not the full documented 99-layer maximum. Its base is resized relative to the source; the analyzer resamples the original to the returned base for comparison and records that alignment. Other reconstruction metrics use the same explicit alignment rule when needed.

A higher max_images permits finer splitting, without guaranteeing the specified count. Poster limit 6 merges three small-print lines into one layer; limit 20 separates them. The product photo splits cup, lemon, vase and flower. Recomposition is approximate: generated backgrounds, shadows, edges and materials can change. Both MAE and PSNR are retained because sparse large edge errors and widespread small texture errors can rank differently; do not infer a universal layer-quality winner from one metric.

With OCR enabled, both poster decompositions return all four standalone text lines correctly (one title plus three information lines). The “ARK 55” text embedded in the blue rectangle stays part of that shape and **does not return independent OCR** in these samples. Nontext layers do not acquire fabricated OCR.

The Arial-authored source title is reported as a visually similar **TikTok Sans**, illustrating approximate font recognition. Color is also approximate (`#1A3F3A` vs source `#173E36` in the max-20 title result). OCR has line boxes and styled runs, not exact font files, point sizes or native PSD text objects.

A local demo omits the title raster layer and renders **“新绿工作室”** into OCR bbox `[88,66,787,174]`, using an explicitly available STHeiti font fitted to the line. It performs **zero additional API calls**. Outside the removed title layer's bbox, the result is **100% pixel-identical to the recomposed generated layers**. This does not make it pixel-identical to the original input; decomposition had already introduced differences.

A separate real `decompose --max-images 10 --text-recognition` CLI smoke check downloads six files and persists OCR in `layers.json`, verifying the CLI path beyond direct-client benchmark calls. Offline regression also verifies index 18, nested OCR preservation, actual background metadata, invalid legacy flags and retry behavior.

## Resulting skill guidance

Default to 5.5; keep Pro/Flash explicit and preserve their actual parameter restrictions. Enable direct text/RGB/multi-reference RGBA, auto background, max_images and structured OCR. Use geometry constraints and checkpoints for edit chains, inspect small text and actual alpha, and prefer local text composition for invariant production copy. Preserve native crop sizes and base-coordinate boxes, with all returned OCR available for downstream tools.

Community research sources and the distinction between firsthand reports, wrapper behavior and official Ark parameters are recorded in [5.5 workflows](../references/seedream55-workflows.md). The official 100-round and global text-error claims remain vendor evidence; this report measures the smaller disclosed corpus above.
