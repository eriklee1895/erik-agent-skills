# 语义分区价值链：从来源到行动

用于来源明确给出「数据 / 输入 → 聚合 → 解释 / 评估 → 使用 / 行动」的技术总览，尤其是用户提供多列精排参考图时。这里演示 **多列构图 + 角色配色**，配色可按文章选择预置、改编或自定义。角色分区、复合区域和走线通道是通用设计手法，不是需要特批的单色例外。

## 从参考图提取什么

先按官方底座只读获取正文、raw 节点和预览，再按需要导出 SVG 或 source。把三个证据分开：

| 证据 | 能说明 | 不能说明 |
|---|---|---|
| 用户截图 / preview | 层级、分区、阅读顺序、视觉气质 | 节点原生类型、绑定、作者写的代码 |
| raw 节点 | 实际坐标、尺寸、色值、字号、形状、连接器端点与分组 | 作者原始生成脚本、导入前的完整 SVG |
| 导出的 SVG | 当前画板的矢量视觉快照，可辅助测量 | 无损创作源、关系绑定、原始代码风格 |

`source` 只在满足底座条件的 Mermaid / PlantUML 画板上能提取代码。返回 `no code blocks found in whiteboard` 时，说明没有可提取的这类代码；不要把导出的 SVG 称为“作者源码”，也不要据此断言作者使用了哪一种工具。

内部原文、原始 raw、人员与账户信息、业务配置及截图留在本地研究目录，不进入可发布 skill。入库的是可泛化的规则和使用通用示意内容独立编写的样例。

## 一次实际节点检查的收获

2026-10-15，经用户授权只读研究的一张内部技术说明画板：逻辑底板 `1680 × 1020`；213 个节点，其中 104 个 `text_shape`、71 个 `composite_shape`、22 个 `connector`、11 个 `image`、5 个 `group`。原始材料不随本 skill 发布。下面是观察值，不是后续绘图必须照抄的数值。

| 观察 | 具体证据 | 可复用方法 |
|---|---|---|
| 四列并非等宽 | 宽度 `330 / 390 / 390 / 240`，列间距均为 `80`；顶端 `y=120`、高度 `680` 一致 | 输入和出口收窄，中间两层分析共享更宽的阅读重心；用共顶、共底稳定节奏 |
| 不同信息用不同内布局 | 聚合列是六张 `354 × 86` 重复卡，纵向步长 `90`；评估列是两列三行网格，再接团队级分析卡 | 重复项严格复用组件；分类关系用局部网格，跨样本分析另成卡，不把全部列都套成相同卡墙 |
| 背景、标题、正文分工 | 近白底；靛 / 青 / 紫 / 琥珀浅底分区；白色内卡；大部分正文深色 | 同一角色复用“浅底 + 浅边 + 深标题”，正文用统一墨色；不要每张卡独立选颜色 |
| 属性标签与主节点分开 | 18 个胶囊形状；主结构主要是 35 个普通圆角矩形 | 胶囊只装短属性、层签或回答范围；有标题与解释的对象用卡片 |
| 外圈线路表达额外论点 | 主链在列间；顶部只连相邻分析列；底部从聚合直达出口 | 主链、回流、直达各用独立通道，保留“无需深度评估也可使用聚合结果”的来源关系 |
| 文本与底板分离 | 104 个独立文本节点，形状自身文字均为空 | SVG 中分别写底板与 `<text>`，标题、正文、编号独立排；是否适合后续整卡移动仍需客户端验证 |

同次检查发现的限制也要保留：104 个文本里有 50 个 12px、8 个 11px；这不是文档默认宽度可读的证明。11 个 `image` 主要是独立三角箭头和装饰弧线；22 条连接器的两端 `arrow_style` 都为 `none`，且按坐标指定。可见的箭头不等于原生有向边，更不等于节点移动后会自动跟随。

## 构图契约

```yaml
grammar: semantic-columns
theme: light-technical
accent_budget: semantic-zones
focal: 中央相邻的两层分析，共同形成比输入与出口更宽的复合焦点
color_semantics:
  indigo: 数据来源
  cyan: 聚合分析
  violet: 语义评估
  amber: 行动出口，不表示预警或失败
relationships:
  - 主链：来源 -> 聚合 -> 评估 -> 行动
  - 回流：评估 -> 聚合，携带语义标签
  - 直达：聚合 -> 行动，无需先经过评估
secondary_band: 来源明确给出的落地步骤；没有这些事实就不画
```

上面的关系是**本原型的示意契约**。用于实际文档时逐条替换为来源事实；没有回流或直达依据时删去相应线，不为套模板补造关系。

中央两列可以同宽、共同聚焦，左右两端保持较窄、较安静。这里的焦点是连续的阅读区域，不要求挑一张卡再染成饱和色。主链是唯一主语法；底部步骤是弱一档的落地带，独立于系统的数据流，不与主链交叉接线。

## 布局配方

1. **先分配宽度，再写卡片。** `可用宽 = 画布宽 - 左右边距 - 3 × 列沟槽`。列宽按标题、最长正文和重复项数量分配；不先四等分再缩字。可从中央两列约各占可用宽的 28–32% 起步，余量给两端，再用文字 fit 调整。
2. **外容器共顶、共底，内部允许不同节奏。** 先固定列头、属性区、内容区的共同起点，再为重复卡指定 `row_y = start_y + i × (height + gap)`。同列的编号、标题、说明各有固定 x。网格列也用 `column_x = start_x + j × (width + gap)`，不逐张目测摆放。
3. **走线沟槽有宽度预算。** 四列总览可从约 `64–80px` 起步；标签宽度加左右留白必须小于沟槽。主链落在共同 y，用中性线。顶部回流只跨相关列；下方直达线在容器底部与落地带之间。不能让反馈文字挤进副标题，也不能让直达标签落到下一排卡片上。
4. **组件层级靠复用建立。** 普通卡白底、1–1.5px 浅边；外容器 1.5–2px 色边。编号圆、层签、小图标只作导航。图标用少量原生 rect / circle / line，复杂图标可省略；不让 path 图标承担架构结构。
5. **落地带承载新信息。** 短标题加轻分隔线，下方三个等高步骤，文字与主链相比弱一档。只有来源明确给出实施顺序才连接箭头；没有顺序的三个建议只并排，不制造先后依赖。

不要照抄参考图的小字密度。继续使用现有字号阶梯与事实删减规则，并计算 `显示字号 ≈ SVG 字号 × 实际显示宽 / viewBox 宽`。例如 1600px 画布显示为 800px 时，16px 文字只剩约 8px。应在真实文档宽度检查：默认视图读不清就减少每卡说明、拆总览与细节；明确用于点开查看的细节板，则在交付中说明阅读方式。单看放大的 PNG 不足以通过默认宽度验收。

## 一套受约束的角色色

这些是本原型的可选值；用户的既有视觉身份仍优先。

| 角色 | 浅底 | 轻边 | 深标题 / 小编号底色 |
|---|---|---|---|
| 来源 | `#EEF2FF` | `#A5B4FC` | `#4338CA` |
| 聚合 | `#ECFEFF` | `#A5F3FC` | `#0E7490` |
| 评估 | `#F5F3FF` | `#DDD6FE` | `#6D28D9` |
| 行动 | `#FFFBEB` | `#FDE68A` | `#92400E` |

画布 `#F8FAFC`，正文 `#0F172A` / `#475569`，普通连线 `#94A3B8`。饱和色只占标题、边界、编号和必要的语义边；四块大底板仍是浅色，不构成四套主题。文字逐项声明实际 `data-bg`。

参考图中的 `#FFFFFF` 对 `#0891B2` 约 `3.68:1`，对 `#D97706` 约 `3.19:1`，不能直接用于小号白字编号。本表改用更深的青色和琥珀色；最终仍以 lint 计算结果为准。

## 连接器要学语义，不照搬三角形

结构性有向边继续使用 `marker-end`，不把 `<line>` 和独立 `<polygon>` 拼成箭头。下例省略了 marker 定义，完整可运行版本见样例：

```svg
<!-- 回流：在相邻两列的上方，不绕整张画布 -->
<polyline data-role="edge" points="992,264 992,224 560,224 560,264"
          fill="none" stroke="#6D28D9" stroke-width="2"
          stroke-dasharray="7 5" marker-end="url(#arrow-purple)"/>
<!-- 直达：独立下通道，不穿过评估列，也不进入落地带 -->
<polyline data-role="edge" points="560,840 560,872 1384,872 1384,840"
          fill="none" stroke="#0E7490" stroke-width="2"
          marker-end="url(#arrow-cyan)"/>
```

原生 connector、结构绑定与拖动行为是三层证据。`--to openapi` 中正确的端点箭头说明方向被保留；raw 的 `attached_object` 说明记录了绑定关系；节点拖动后端点是否跟随，仍需客户端实测。坐标端点不能作为绑定证明。

python3 scripts/fit_check.py evals/fixtures/semantic-value-chain.svg --json
