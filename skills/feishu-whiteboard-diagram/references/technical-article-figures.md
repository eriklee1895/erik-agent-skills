# 技术文章成套图：统一视觉，按关系换构图

适用于一篇文章有多张解释图，或单图需要表达共享输入、模块协同、跨层控制、体验到指标的映射。这里补充 [构图](composition.md) 的选型方法，不新增固定主题；单图仍遵守事实契约、文字适配与原生转换要求。

## 先列图的分工，再统一视觉

在工作笔记中为每张图写「读者问题 / 主语法 / 来源事实 / 本图省略什么」。以下是可选分工，不是必须凑齐的图数或固定顺序：

| 读者问题 | 合适的结构 | 图中保留的重点 |
|---|---|---|
| 结果改善了多少？ | 摘要指标 + 证据面板 | 指标范围、基线、变化量；详见 [定量报告](data-report-style.md) |
| 能力如何演进？ | 阶段带 + 里程碑轴 | 大阶段与具体事件分层 |
| 方案由哪些工作共同构成？ | 总览分区 + 对应细节 | 并行工作不因编号而变成串行依赖 |
| 输入为何走不同通道？ | 输入分类 → 通道 → 策略 | 分类依据与通道属性 |
| 两层如何协作？ | 分层 + 数据 / 控制通路 | 层间接口与两类边的含义 |
| 体验问题对应哪些可观测对象？ | 阶段与指标映射 | 一对多、多对多的真实关系 |
| 多个模块怎样共同决策？ | 共享输入 + 双模块 + 汇合 | 共同输入、横向信号、独立输出 |

共享的是字体阶梯、正文墨色、浅底、边界、圆角、间距和标签样式。画布比例、高度、列数、标题对齐和主阅读方向随内容调整。同一角色跨图再次出现时维持含义；局部图例可重新定义数据系列色，不能让读者把“角色蓝”误当作“端 A 蓝”。

可从现有 Light Technical 改编出白卡、蓝 / 青绿强调、少量暖色注释的组合，也可以沿用品牌色。让饱和色集中在薄顶边、短标题、编号和必要标记，卡片正文保持深色。颜色只为角色或层级服务时，不需要每卡换色，也不把蓝 / 绿自动解释成优劣。

## 白卡、薄顶边与接口标签

一张模块卡可按需包含：短角色标签 → 模块标题 → 一两行职责 → 输入 / 输出。只有关系复杂时才加接口区；简单步骤无需填满这些槽位。

- **薄顶边建立重复节奏。** 用原生 `rect` 做一条实心色带，内收于卡片圆角即可；不必为贴合顶角引入 `clipPath`、装饰 path 或图片。标题与色带共享角色色，正文使用统一墨色。
- **端口标签解释交换内容。** 箭头旁写“观测摘要”“分类信号”等内容名；卡内写输入 / 输出摘要。标签靠近对应通道，留出完整可见的箭头，不用大胶囊盖住短边。
- **同类卡复用内部对齐线。** 标题、说明、接口区采用相同 x / y 节奏。共享输入和最终决策可以横跨整行，中间模块保持等高；整图不需要唯一最大卡。
- **用真实接口决定边。** 先列出 `来源 → 目标：内容`，再定位端点。位置接近、相同颜色、编号连续都不能替代依赖证据。

## 共享输入 → 双模块 → 汇合决策

当来源给出 `S→A、S→B、A→B、A→C、B→C` 时，可采用一行共享输入、下一行两个模块、末行汇合决策：

```text
┌──────────────── 共享输入 S ────────────────┐
       │ 观测摘要                    │ 观测摘要
       ▼                             ▼
┌──── 模块 A ────┐   分类信号   ┌──── 模块 B ────┐
│                │ ──────────→ │                │
└────────────────┘             └────────────────┘
       │ A 的结果                    │ B 的结果
       ▼                             ▼
┌──────────────── 汇合决策 C ────────────────┐
```

这表达两个模块共享上游，并且存在横向影响；它不声称 A、B 完全独立并行。不要压成 `S→A→B→C`，否则丢失 `S→B` 与 `A→C`。实际来源没有横向信号时删去那条边；没有共同输入或汇合时选择其它结构。

先定两张中间卡的宽度与接口文字，再给中间沟槽分配宽度。可从 `1440` 宽画布、两侧 `80`、两卡各 `560`、中间 `160` 起步；上下通道约 `88–96`。这些只是随文样例的几何，不是全局尺寸。用 20–26px 的接口与模块文字，仍需按目标显示宽度折算和检查。

独立编写的通用样例：[shared-input-decision.svg](../evals/fixtures/shared-input-decision.svg)。它用任务调度的示意事实保留上述五条关系；顶边、卡片、文字和箭头均走原生形状转换。

## 两层协作：把数据和控制分别编码

层容器说明归属，连线说明交互。仅有上、下两层不能推断调用方向。

可以用实线表示数据、虚线表示控制 / 状态反馈，并在图例写明；颜色负责区分层，线型负责区分边，避免一条颜色同时承担两种解释。虚线不天然等于“失败”“可选”或“异步”。按来源给出的上下行分别布线，不为了对称补回路。

把跨层接口标签放在层间留白。共享缓冲区、调度器或总线可画成横向长条，多个生产者接入；只有来源确实共享时才使用这种合并。长条占据横向空间本身就表达共同使用，无需再复制成多份节点。

## 阶段与指标映射：对齐也是一种声明

“上面阶段、下面指标、同列一根箭头”很清楚，但也暗示一一对应。先建立关系清单，再决定是否对齐成列：

```text
指标 X → 进入阶段、分析阶段
指标 Y → 回答阶段
```

若箭头表示“影响”，按上面的方向画；若从阶段指向指标，要在图中说明边表示“观测 / 定位到”，保持同一种方向含义。多阶段共用指标时，可以画共享指标卡并连接各阶段，或改成带明确关联标记的小矩阵。不能只保留最整齐的同列线而漏掉跨列关系。

横向阶段箭头表示交互顺序，纵向关联表示指标映射，两者应有不同标签或清楚的分区说明。底部公共指标带表示“共同使用的观测集合”时，连到集合边界即可；不要让箭头恰好落在某张内部卡上而造成额外一对一含义。

## 时间线：阶段带与事件卡分工

上方宽条说明阶段，中轴放事件锚点，事件卡可上下交替以减小拥挤。同类事件采用相同卡片节奏；日期、名称和必要证据分层。阶段范围应与其覆盖的里程碑对齐。

等距事件轴用于叙事顺序时标“示意，非按时间比例”；用于比较间隔或速度时按真实时间定位。不要把等距年份暗示成等长工期。另一个截面的规模 / 分布可以是独立辅助面板，但它必须提供新信息且有自己的尺度；过密时拆图。

## 研究参考图时保留的边界

读取路径与证据分工沿用 [semantic-columns.md](semantic-columns.md#从参考图提取什么)。原图中的内部内容、token、截图和 raw 留在本地研究目录；skill 只保存通用方法和独立示例。

- 视觉上连续的薄色带或箭头也可能是 `image`。检查 raw 后再判断可编辑性；复现结构优先使用原生 `rect` 与带 marker 的 connector。
- `position` 端点与 `attached_object` 端点应分别统计；某些边有绑定，不代表整板都有。存在绑定字段也不能替代客户端拖动验证。
- raw 中有 shadow / opacity，不能证明从 SVG 输入这些效果也会保真。继续按现有 parser-contract 选取可稳定转换的元素。
- 精美参考也可能含大量 7–13px 小字。提取层级与节奏，不复制小字密度；在目标文档宽度阅读，必要时减少说明或拆图。
- 统计摘要、色彩和等列布局都要回到正文核实；视觉认可不等于数据口径、映射关系或编辑行为已验收。
